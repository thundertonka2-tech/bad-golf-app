# VERIFY_SERVER — independent re-check of the server-side League defects (build e5a912f)

**Method.** Every repro is my own, written from scratch with my own inputs and hand-worked expected results. None of the other tracks' harnesses were used. Each scenario ran on the live project `ojclesuwxhtzvrymqrwg` as one `execute_sql` call wrapped in `begin; … rollback;`. Every row was created inside that block under ids `00000000-0000-4000-bbbb-*`. There were no UPDATE/DELETE statements on pre-existing rows.

**Why live and not local.** The local copy at `/var/tmp/qa_pools_pg` (db `pools`) has only 6 `league_*` functions, against 130+ on live. It is not a usable mirror, so it was not relied on.

**Function bodies.** I read them from live with `pg_get_functiondef`. The md5 of every `league_*` function was taken at the start of the run.

**Live exposure.** Measured with one read-only SELECT. There are 4 live seasons: 1 `stroke_net / net_stroke` and 3 `scramble / match_only`. None of them has hcp_rules par-3 or max score, aggregate, playoffs, any weekly pot, a buy-in with late members, team_4man, or a 9-hole week. All 4 use witness presence.

**Files.**
- Scripts: `verify_server/00_prelude.sql`, `S1_hcp.sql`, `S2_team_playoffs.sql`, `S3_pools.sql`, `S4_cards_subs.sql`, `S5_holes.sql`.
- `verify_server/build.sh` wraps one scenario in begin/rollback.
- Raw outputs are in `verify_server/results.log`.

**Note on my course.** The test course's pars sum to 71, although its label says 72. Every expected value below is worked from 71.

## Duplicates and shared roots
- **SETUP-1 = SCORING-1.** Same root: `league_card_place` / `league_strokes_on_hole` take no par. One fix.
- **SCORING-2 and SCORING-3** both come from `league_team_net(..., 'aggregate')` returning a summed per-hole net that `league_matchup_points` then treats as one player's net. Fix them together.
- **LIFE-6 and LIFE-7** share `league_respond_sub_invite`: it has no own-fixture, second-seat or resolution check, and `league_resolve_absence` leaves invites pending. LIFE-6's `assign_sub`/`claim_sub` part is the same missing "already holds a seat this week" check.
- **SETUP-2 and SETUP-7** both come from `league_card_place` / handicap storage trusting whatever `league_handicaps` holds (or doesn't hold). They are separate fixes, but the same review.
- **HOLES-5** belongs to the client track, not the server track.
